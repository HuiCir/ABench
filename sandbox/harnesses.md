# Harness adapters (v1)

All adapters implement the same runner contract and are selected by
`harness.kind` in the sandbox manifest. The runner creates the workspace and
environment before invoking an adapter; the adapter never chooses mounts or
retention policy.

## Direct Python

```yaml
harness:
  kind: python
  entrypoint: submission/run.py
  args: ["--config", "/run/abench/run-config.json"]
  python: /opt/abench/bin/python
  timeout_sec: 900
```

The runner executes the entrypoint from the submission root with the generated
environment. A Python harness must write only to `ABENCH_WORKSPACE`,
`ABENCH_CHECKPOINT_DIR`, and `ABENCH_SUBMISSION_DIR`.

## Claude Code print mode

```yaml
harness:
  kind: claude_code_cli
  binary: claude
  prompt_file: /run/abench/agent-prompt.md
  args: ["-p"]
  timeout_sec: 1800
  max_output_bytes: 10485760
```

The adapter constructs the equivalent command (the exact permission flags are
part of the hashed adapter configuration; the smoke-only bypass is safe only
inside the disposable workspace):

```text
claude -p "$(cat /run/abench/agent-prompt.md)" \
  --output-format stream-json \
  --permission-mode bypassPermissions \
  --no-session-persistence \
  --add-dir "$ABENCH_WORKSPACE" \
  --add-dir "$ABENCH_CASE_DIR" \
  --add-dir "$ABENCH_SOURCE_DIR" \
  --add-dir "$ABENCH_DATA_DIR" \
  --dangerously-skip-permissions  # smoke only
```

The canonical manifest kind is `claude_code_cli`; `claude_code_p` is accepted
as a backwards-compatible alias. The prompt is generated by the runner and includes the case contract, mounted
resource paths, output requirements, and the one-shot submission rule. The
adapter captures the CLI's stdout/stderr as diagnostics; it does not treat
model-generated text as a result. A successful run still requires an actual
validated submission directory and server-generated metrics. If the installed
CLI has a version-specific print-mode flag, the adapter may add it through
`args`; the local runner CLI flag `--harness claude` selects this adapter and
the sandbox remains offline.

## Shell or container

```yaml
harness:
  kind: container
  image: abench/ds-gbm:smoke-v1
  entrypoint: ["python", "submission/run.py"]
  args: []
  timeout_sec: 900
```

The image digest is part of `resource_hash`. A host path, package install, or
network endpoint is invalid even if the image command requests it.

## Common adapter checks

Before launch: validate the entrypoint, args, environment allowlist, and image
or binary hash. During launch: record process tree, stdout/stderr, wall time,
memory, accelerator telemetry, and event hash chain. After launch: validate
the one-shot submission and emit a `result_manifest` regardless of exit code.
