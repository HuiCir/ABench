## Conclusion

1. All statistics in the documents check out, the smoke-run artifacts are complete, and the agent itself behaved honestly.
2. "Dataset construction" is so far only done at the contract level, with no real data: none of the 98 cases' resource registries contains a real SHA256 or a single license field. The only actual data is a 384-row synthetic fixture.
3. Two issues were found that must be fixed before the next run:
   - a smoke record can pass the "real provenance" gate of formal scoring;
   - the sandbox profile is not enforced by the runner, and the agent receives the host's full environment.

## P0: must fix before the next run

### 1. A smoke record can pass the "real provenance" gate of formal scoring

- In `tools/sandbox_runner.py`, the `run.jsonl` record hard-codes `"provenance": "benchmark_real"` (around line 604), including for smoke runs.
- But the `result_manifest.json` of the same run says `smoke_real`.
- Validating this smoke record against DS-GBM-001's `run_schema.json`, jsonschema accepts it. B-OPT-001's `run_case.py` also accepts `benchmark_real` as real provenance.
- As a result, "smoke runs do not enter the leaderboard" currently relies only on convention; no code enforces it.

**Fix**:
- With `--smoke`, write provenance `smoke_real` in `run.jsonl`.
- Add a required `run_mode` field to `run_schema.json`.
- Every scorer rejects records with `run_mode != benchmark` or `formal_score == null`.

### 2. The sandbox profile is not enforced, and the agent can read the host's full environment

`sandbox/profiles/mps_smoke_ds_gbm.yaml` declares `network: disabled`, `env_allowlist`, `read_only`, `forbidden` and `host_filesystem: inaccessible`. But the runner never reads this file. Specifically:

- **Environment variables**: `env = os.environ.copy()`, so the agent process inherits the host's full environment, which may include credentials for the endpoint used by the Claude API control plane. `redact_env` applies only to logs, not to the environment passed to the agent.
- **Permissions**: smoke mode adds `--dangerously-skip-permissions` and `bypassPermissions`, and runs under `/var/folders/...` on the macOS host. The agent can in effect run any command and read the whole user directory.
- **Read-only data**: `data_view` is a symlink to `sandbox/fixtures`, so the agent can write through to the original fixture.
- **Network**: no proxy or firewall is set. `network_used: false` is a value the agent hard-coded in `run.py`, not a measurement.
- **Memory limit**: `RLIMIT_AS` has no effect on macOS.
- **Manifest hash**: `sandbox_manifest_sha256` hashes the runner's own configuration, not the profile file.

`BENCH_ASSESSMENT.md` already admits this is a soft sandbox, but the profile and result files still state "network disabled, host inaccessible", and readers will assume these are enforced.

**Fix** (until the container backend is ready):
- Build a clean environment from the profile's `env_allowlist`, passing in addition only the one credential variable the Claude CLI needs.
- Run the claude harness as a separate macOS user or in a container, and stop using `--dangerously-skip-permissions`.
- Copy the data into a read-only copy instead of using a symlink.
- The runner reads and hashes the profile file; `result_manifest` records, item by item, the actual enforcement level of each security claim: `enforced`, `best_effort` or `not_enforced`.

## P1: affects the credibility of results

### 3. All metrics are self-reported by the agent

The `metrics` in `run.jsonl` and `result_manifest.json` are a verbatim copy of the `metrics.json` the agent wrote:

- `test_accuracy` was computed by the agent itself using the public test labels;
- `elapsed_seconds` was timed by the agent itself.

The only things actually measured on the server side are wall time 123.9 s, CPU time 6.7 s and peak memory 318 MB. That is acceptable for a pipeline smoke run, but it contradicts the spec requirement that "the scorer rejects self-reported metrics".

**Fix**: add a server-side evaluation entry point. The runner loads the agent's checkpoint or prediction file and computes metrics on data whose labels the agent cannot see.

### 4. The instructions the agent actually received cannot be reconstructed

Several pieces of information disagree:

- the example command in `spec/sandbox_runner.md` requires only 3 submission files, while the actual run requires 7;
- `sandbox/prompts/ds_gbm_001_mps_smoke.md` says "write only 3 files", while the agent wrote 7;
- by default the runner uses the case's full `task_prompt.md` (the formal task over 20 OpenML datasets) plus a smoke suffix;
- the runner records neither the prompt hash nor the full command-line arguments.

It is therefore impossible to confirm which prompt and which arguments this run actually used.

**Fix**: `result_manifest` records the prompt's sha256, the full argv (with credentials redacted) and where the list of required submission files came from.

### 5. Choice of smoke case and data notes

- **Case and device mismatch**: DS-GBM-001 is a `cpu_only: true` tabular case in the resource registry, yet the smoke run trained an MLP on MPS. This run validated only the pipeline and used nothing specific to this case. To validate MPS, use a micro-scale version of a GPU case instead.
- **Fixture split does not match the profile**: the fixture is 12-dimensional Gaussian synthetic data with 256 training and 128 test rows and no dev set, while the profile says `split: train_dev_test`.
- **Fixture provenance not recorded**: the fixture is generated by `build_data` in `tools/smoke_ds_gbm.py` and is already standardized with training-set statistics, but the generating command and version are not written into any provenance record.
- **The result says nothing about model capability**: a linear least-squares baseline reaches 0.945 test accuracy on this data, and the MLP the agent trained for 2 epochs reaches 0.883. These numbers only show the pipeline runs and must not be cited as conclusions about any model's capability.

### 6. The demo path of B-OPT-001 is broken

`scoring/run_case.py` now requires run records with "real provenance", so the `make_mock_runs.py && run_demo.py` commands on lines 81–82 of the README exit with an error. The scoring demo of B-OPT-001 on the site uses old output that can no longer be regenerated.

**Fix** (either one):
- add an explicit `--allow-simulated` switch and watermark its output;
- or remove the demo commands from the README.
