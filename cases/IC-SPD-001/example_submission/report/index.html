ResNet-9 Speedrun Baseline: A GPU-Resident Data Pipeline with One-Cycle Training

ABench reference submissionStandard reference for task statement standard v2.1 (a baseline that does not aim to be fastest)
Abstract

This submission gives a baseline for the CIFAR-10 speedrun task: a 9-layer residual convolutional network(Page, 2018; He et al., 2016) with a one-cycle learning rate(Smith & Topin, 2017), label smoothing(Szegedy et al., 2016) and cutout(DeVries & Taylor, 2017). The design focus is to keep every step inside the timed window on the GPU: training images are moved to GPU memory once, normalization and augmentation are done per batch in GPU memory, and forward and backward passes use bfloat16 and the channels_last layout. At inference, the logits of the original and horizontally flipped images are averaged.

1Introduction

This task is judged by the wall-clock time needed to train to a given accuracy, and the timing covers module import, data transfer, compilation and training. Two things therefore matter at once: how many parameter updates are needed to reach the accuracy threshold, and how long each update takes on the reference card. The former depends on the network, optimizer and regularization; the latter on operator shapes, numerical precision, memory layout and synchronization between host and device. The anchor work(Jordan, 2024) shows that improvements on both sides compound.

As a reference version, this submission uses only mature, easily reproduced components; the aim is a starting point that is complete in interface, timing and report format. The room for improvement is left to the entries.

Changes relative to the anchor. Each item states what this submission does differently and where it is in the code.

  1. Page's 9-layer residual network and procedure replace the anchor's network and training tricks. — method.py: ResNet9, train
  2. The whole data pipeline, including augmentation, runs on the GPU in bfloat16. — method.py: _augment, train
  3. Prediction averages the logits of the original and horizontally flipped images. — method.py: predict

2Related Work

Residual networks and batch normalization

Residual connections make deeper convolutional networks easy to optimize(He et al., 2016); batch normalization allows larger learning rates(Ioffe & Szegedy, 2015). Page's series of posts improved the training procedure step by step on the DAWNBench CIFAR-10 task, arriving at a 9-layer residual network and bringing single-GPU training to 94% down to tens of seconds(Page, 2018).

Optimization and regularization for short training

A one-cycle learning rate rises and then falls, using large learning rates within a small number of epochs(Smith & Topin, 2017); Nesterov momentum is stable and reliable in this setting(Sutskever et al., 2013). Label smoothing and cutout provide regularization matched to the model capacity.

These components were tuned for older hardware and do not use the anchor's later changes to the network, optimizer and data order; closing that difference on the reference card is the gap left to entries.

3Method

3.1Network architecture

Let CB(c) denote "3×3 convolution → batch normalization → ReLU" with c output channels; CBP(c) inserts a 2×2 max pooling after the convolution; R(c) is two CB(c) blocks plus an identity skip. The network is

f(x)=18Wmaxpool(R(512)CBP(512)CBP(256)R(128)CBP(128)CB(64)x) (1)

where W∈ℝ10×512 is a bias-free linear classifier whose output is multiplied by 1/8 to reduce the scale of the initial logits(Page, 2018). The final global pooling takes the maximum rather than the mean.

3.2Data pipeline and training objective

At the start of train the training images are moved to GPU memory once, normalized by per-channel mean and standard deviation, and converted to the channels_last layout. Each epoch generates one augmentation of the whole set in GPU memory: 4-pixel reflect padding followed by a random crop back to 32×32, a horizontal flip with probability 1/2, and an 8×8 square zeroed at a random position(DeVries & Taylor, 2017). The random crop is done in 81 shift groups, avoiding a per-sample loop. The loss is cross-entropy with label smoothing ϵ=0.2(Szegedy et al., 2016):

ℒ=−∑k((1−ϵ)𝟙[k=y]+ϵ/10)logsoftmax(f(x))k (2)

The learning rate rises linearly from 0 to 0.4 over the first 20% of steps and then falls linearly to 0:

ηt=0.4·min(t/tw,(T−t)/(T−tw)),tw=0.2T (3)

The optimizer is SGD with Nesterov momentum 0.9(Sutskever et al., 2013), batch size 512, 24 epochs; weight decay 5×10−4 applies only to the weights of convolutional and linear layers, not to batch-normalization parameters.

3.3Algorithm

This corresponds to train, _augment and ResNet9 in method.py. predict runs inference in batches of 2,000 images and averages the logits of the original and horizontally flipped images. The training loop contains no operation that forces a host synchronization.

3.4Complexity

The network has about 6.57 million parameters. The forward pass of one 32×32 image takes about 3.8×108 multiply-adds, most of them in the two 512-channel residual convolutions and the 256→512 convolution. Estimating the backward pass at about twice the forward, one epoch of 50,000 images costs about 1.1×1014 floating-point operations, and 24 epochs about 2.7×1015. Memory use comes mainly from the training images held in GPU memory (about 0.6 GB in float32) and the activations of a 512 batch, far below 24 GB.

4Design Rationale

The timed window is measured in seconds, so host-side data loading and per-step synchronization easily become bottlenecks. With data and augmentation both in GPU memory, the training loop is a continuous stream of GPU kernels and the GPU never waits for the host. channels_last and bfloat16 let convolutions take the fast tensor-core path; bfloat16 has the same exponent range as float32, so no loss scaling is needed.

The network uses only 64 and 128 channels at 32×32 resolution, and its computation is concentrated in high-channel layers at the low resolutions of 8×8 and 4×4. This keeps memory traffic per multiply-add low and makes it easier for operators to reach high utilization. The 1/8 scaling before the classifier and label smoothing both reduce the risk of oversized logits early in training, which permits a larger peak learning rate.

Differences from existing methods

This reference version largely follows Page's network and training procedure(Page, 2018), only moving the whole data pipeline to the GPU and using bfloat16. It does not adopt the more aggressive techniques of the anchor work(Jordan, 2024), so it is not a new method and serves only as the standard reference for format and process.

5Scope and Limitations

The 24 epochs and the one-cycle learning rate are set for 50,000 training images; with a smaller training set (such as the 45,000 images of the self-check), each epoch has fewer steps and the total number of updates at the same epoch count drops accordingly. The shift-grouped crop performs 81 masked copies per epoch, and this cost grows with more images. The max pooling and global max pooling in the network suit 32×32 inputs; at higher resolution the number of downsampling stages must be reset.
