Draft-Model Speculative Decoding with an Adaptive Draft Length

ABench reference submissionStandard reference for task statement standard v2.1
Abstract

This submission applies the anchor's speculative decoding (Leviathan et al., 2023; Chen et al., 2023) with the provided Qwen2.5-0.5B-Instruct as draft and greedy verification by the fp32 target: each round the draft proposes k tokens, the target scores them in one forward pass, and the longest agreeing prefix plus the target's own next token is kept, so the output is the target's greedy output. The draft length moves between 1 and 8 with the recent acceptance, in the spirit of later adaptive schemes. The decoding loop was checked against plain greedy decoding in a mock; it has not been timed, since PyTorch and the models were not available where the case was built.

1Introduction

Autoregressive decoding of a small model is limited by memory bandwidth: every token reads all weights once. Speculative decoding lets a cheaper model guess several tokens that the target checks in one pass; when guesses are right, several tokens cost one target pass. How much it helps depends on the workload, so the case includes one where agreement is expected to be low.

2Related Work

Speculative decoding with a draft model was introduced by Leviathan et al. and Chen et al. (Leviathan et al., 2023; Chen et al., 2023); Medusa trains extra heads on the target to draft without a second model (Cai et al., 2024); EAGLE drafts at the feature level (Li et al., 2024); SpecInfer verifies token trees (al., 2024); lookahead decoding needs no draft at all (Fu et al., 2024).

3Method

The target (fp32) prefills the prompt and the draft (bf16) the prompt without its last token. Each round the draft consumes the tokens it has not seen and proposes k tokens greedily; the target processes its last token and the k proposals; n leading proposals that equal the target's argmax are accepted, followed by the target's argmax at position n. Both caches are cropped to the accepted length. k increases after a fully accepted round and decreases after a round that accepted fewer than half.

4Design Rationale

Greedy verification makes the output exactly the target's greedy output, which the case requires; running the target in fp32 as the evaluator does avoids mismatches from lower precision; the adaptive k keeps the cost of rejected proposals low on workloads where the draft disagrees.

5Scope and Limitations

The draft is not adapted to the target, verification is a single chain rather than a tree, and the speedup has not been measured yet.
