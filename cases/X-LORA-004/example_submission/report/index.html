LoRA on Query and Value Projections: The Reference Parameter-Efficient Fine-Tuning for GLUE

ABench reference submissionStandard reference for task statement standard v2.1
Abstract

This submission is the anchor's GLUE recipe for roberta-base (Liu et al., 2019): rank-8 low-rank updates ΔW = BA with scaling α/r = 2 added to the query and value projections of all twelve layers, B initialised to zero so that training starts from the pretrained function, plus a freshly initialised classification head on the first token (Hu et al., 2022). Each task trains its own 887,042 parameters with AdamW, linear warm-up over 6% of the steps and linear decay. The method is the reference against which entries are compared under the same million-parameter cap.

1Introduction

Fine-tuning all 125M parameters of roberta-base per task is expensive to store and serve. LoRA observes that the weight change needed for adaptation has low intrinsic rank and parameterises it as a product of two thin matrices, adding no inference latency once merged (Hu et al., 2022; Aghajanyan et al., 2021). Under a fixed parameter budget the question becomes where and how to spend it.

Changes relative to the anchor. Each item states what this submission does differently and where it is in the code.

  1. The anchor's LoRA on query and value projections at rank 8, α = 16, is kept unchanged. — peft.py: LoRALinear, build
  2. A trainable dense-plus-output classification head on the <s> token is counted in the task-specific budget. — peft.py: Head
  3. Per-task schedules (epochs, peak learning rate, warm-up then linear decay) are fixed in the training program. — train.py: SCHEDULE, train_task

2Related Work

Adapters insert small bottleneck layers (Houlsby et al., 2019); BitFit trains only biases (Zaken et al., 2022); LoRA adds trainable low-rank matrices to existing projections (Hu et al., 2022). On GLUE with roberta-base the anchor applies LoRA to the query and value projections with rank 8 and trains the classification head.

LoRA spends its budget uniformly on the query and value projections; adapters, prompt tuning and scaling vectors spend it elsewhere; how to allocate a fixed budget across modules and layers is the gap.

3Method

3.1Parameterisation and training

For W ∈ {W_q, W_v} of each layer, the forward pass computes Wx + (α/r)·B(Ax) with A ∈ R^{r×768} initialised with Kaiming-uniform values, B ∈ R^{768×r} initialised to zero, r = 8, α = 16. The head maps the <s> token through a 768 × 768 dense layer with tanh and a 768 × 2 output layer. Per task: AdamW (weight decay 0.1), batch 32, sequences truncated to 128 tokens, bf16 autocast, peak learning rate 5e-4 (4e-4 for CoLA), 10 epochs for RTE and MRPC, 8 for CoLA, 2 for SST-2.

3.2Complexity

Each wrapped projection adds 2 · 768 · r = 12,288 parameters, 294,912 in total, and 592,130 for the head. The extra compute per token is O(r · d) per wrapped projection, negligible next to the frozen encoder.

4Design Rationale

Zero-initialising B means the first forward pass reproduces the pretrained encoder, which keeps early training stable on small datasets such as RTE. The α/r scaling makes the effective learning rate of the update insensitive to the rank. Training the full head is the main use of the budget; the cap leaves about 113,000 parameters unused.

5Scope and Limitations

Placement (only query and value), a uniform rank across layers and a large head are fixed choices, not optimised for the cap; allocating the budget across layers and modules, or reducing the head, are directions for entries.
