Muon with Update-RMS Matching, Transferred Unchanged to a Vision Transformer

ABench reference submissionStandard reference for task statement standard v2.1
Abstract

This submission gives the reference point for transferring language-model optimizers to vision transformers: the anchor's recipe applied as-is. Weight matrices are updated with Muon, i.e. Nesterov momentum orthogonalised by a quintic Newton–Schulz iteration (Jordan et al., 2024), scaled by 0.2·sqrt(max(rows, cols)) so that the update RMS matches that of AdamW and the learning rate and weight decay can be shared (Liu et al., 2025). All other parameters use AdamW (Loshchilov & Hutter, 2019). Nothing is adapted to vision; that adaptation is what the task asks of entries.

1Introduction

Orthogonalised updates have become a strong alternative to Adam-type methods for language-model pretraining (Jordan et al., 2024; Liu et al., 2025). Vision transformers differ in ways that may matter to an optimizer: much smaller widths, a linear patch embedding whose input dimension is tiny (48), heavy data augmentation, and short training measured in epochs (Dosovitskiy et al., 2021). A faithful transfer of the anchor is the natural baseline.

Changes relative to the anchor. Each item states what this submission does differently and where it is in the code.

  1. Muon is applied to weight matrices unchanged, with update RMS matched to AdamW by 0.2·sqrt(max(rows, cols)). — optimizer.py: MuonRMS.update
  2. All non-matrix parameters use AdamW. — optimizer.py: MuonRMS.update (else branch)

2Related Work

Muon replaces the momentum matrix M by an approximation of its polar factor UVᵀ, computed with a few Newton–Schulz iterations, so that all singular directions are updated at the same rate (Jordan et al., 2024). The anchor shows that adding decoupled weight decay and scaling the update to match the RMS of AdamW updates makes Muon work at scale with AdamW's hyperparameters (Liu et al., 2025).

Muon was tuned for language models; vision transformers differ in width, embedding shape and augmentation, and no adaptation of the update rule to them is part of this reference, which is the gap.

3Method

3.1Update rule

For a matrix parameter W with gradient G: m ← μm + G, N ← G + μm, O ← NS5(N) · 0.2·sqrt(max(r, c)), ΔW = −η(O + λW), with μ = 0.95 and λ = 0.05. For every other parameter: bias-corrected AdamW moments with β = (0.9, 0.99) and no weight decay. The framework supplies η (with warm-up and cosine decay) and uses 0.15η for one-dimensional parameters.

3.2Complexity

For an r × c matrix with r ≤ c, five Newton–Schulz steps cost O(r²c) each; the state is one momentum matrix per weight and two moments per non-matrix parameter, well under the 3× limit.

4Design Rationale

Update-RMS matching decouples the choice of learning rate from the matrix shape, which matters in a ViT where the patch embedding (192 × 48), attention (576 × 192) and MLP (768 × 192) matrices have very different aspect ratios. Keeping AdamW for gains, biases, the class token and the position embedding follows the anchor, which applies Muon only to hidden weight matrices.

5Scope and Limitations

Whether the patch embedding and the classification head should be orthogonalised, how augmentation noise interacts with momentum, and whether the RMS target should depend on width are left open; these are the questions an entry should answer.
