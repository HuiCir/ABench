GRPO with LoRA and a Small Format Reward

ABench reference submissionStandard reference for task statement standard v2.1
Abstract

This submission applies Group Relative Policy Optimization (Shao et al., 2024) to Qwen2.5-0.5B-Instruct through low-rank adapters (Hu et al., 2022). For each prompt, eight responses are sampled; their verifier rewards are standardised within the group to give advantages, and the policy takes one on-policy gradient step on the token-level objective without a KL penalty, as later practice such as DAPO recommends (Yu et al., 2025). Half the prompts are Countdown instances from the case's generator, half GSM8K training problems (Cobbe et al., 2021).

1Introduction

Verifiable rewards let a small model learn from its own correct and incorrect attempts without a reward model. The case asks how to turn them into the largest accuracy gain within a fixed rollout budget.

Changes relative to the anchor. Each item states what this submission does differently and where it is in the code.

  1. A 0.1 reward for a single well-formed but wrong answer block is added to the verifier reward. — train.py: reward

2Related Work

GRPO replaces PPO's value function with group-normalised rewards (Shao et al., 2024); DAPO drops the KL term, decouples clipping and filters prompts whose groups carry no signal (Yu et al., 2025). GSM8K provides grade-school problems with numeric answers (Cobbe et al., 2021).

3Method

Reward 1 for a verified answer, 0.1 for a single well-formed but wrong answer block, 0 otherwise. Sixteen prompts per step, eight samples each at temperature 1 and at most 384 new tokens; advantages are the group-standardised rewards; the loss is the advantage-weighted log-probability of the response tokens averaged over all tokens of the batch; AdamW at 2e-5 on rank-16 LoRA parameters, 200 steps; steps whose groups all tie are skipped.

4Design Rationale

The small format reward keeps the answer block from disappearing early in training; LoRA keeps memory low so that the budget goes to rollouts.

5Scope and Limitations

One update per batch (no clipping needed, but sample-inefficient), no length control and no curriculum. It has not been run here.
