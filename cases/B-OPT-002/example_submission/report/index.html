RidgeSign: A Frozen-Grammar Searched Optimizer with Fast/Slow Momentum and Confidence Gating

ABench example submission ABench submission (format example, not a real entry)
Abstract

RidgeSign combines, from frozen first-order update primitives, exponential moving averages at two time scales, an extrapolation term, a continuous confidence magnitude and a direction filter. It keeps Lion's sign update and small state cost, while letting the magnitude vary smoothly with the agreement between the fast and slow momenta. The search process enumerates legal programs with a fixed seed, ranks candidates on a deterministic proxy stream, and writes the full candidate sequence and the chosen program to the search log. This paper gives the rule definition, search interface, complexity and scope; self-reported scores in the search log are not a basis of this design report.

1Introduction

Lion produces a sign direction from a single exponential moving average; the program is short and its state cheap(Chen et al., 2023). A single time scale cannot distinguish stable signals from short-lived perturbations when the gradient direction flips often; a constant sign magnitude also gives coordinates with weak signals the same step as those with strong signals. The frozen interface of B-OPT-002 requires candidates to be composed only of the given symbolic primitives, and requires the search to be replayable item by item.

The key points of RidgeSign's design are:

  • maintain fast and slow first-order states in parallel and express short-term change with an extrapolated difference;
  • modulate the magnitude of the sign direction with a bounded, continuous confidence factor;
  • represent candidate programs as frozen ASTs and produce a replayable sequence with a fixed traversal order and seed.

Changes relative to the anchor. Each item states what this submission does differently and where it is in the code.

  1. Fast and slow first-order states with an extrapolated difference replace Lion's single interpolated momentum. — optimizer.py: RidgeSign.update
  2. A bounded confidence factor |z|/(|z|+τ+ε) modulates the magnitude of the sign direction, which Lion keeps constant. — optimizer.py: RidgeSign.update
  3. A difference gate q suppresses steps when the fast state falls behind the slow one. — optimizer.py: RidgeSign.update
  4. The rule was selected by a replayable search over frozen ASTs of the given primitives. — search.py: programs

2Related Work

Adam scales coordinates adaptively with first- and second-order exponential averages(Kingma & Ba, 2015); AdEMAMix shows that combining fast and slow momenta can express longer time scales than a single EMA(Pagliardini et al., 2024). RidgeSign borrows only first-order states and linear combinations, introducing no second-order state, to fit the state budget of the frozen primitives.

Program search

Symbolic discovery methods write the update rule as a program in a finite grammar and screen candidates on a small proxy stream(Chen et al., 2023). RidgeSign keeps the same "frozen grammar, deterministic replay" boundary: the searcher only generates and ranks ASTs, and the optimizer itself never reads the search log.

The boundary of learned optimizers

Learned optimizers treat the update rule itself as the object to be learned and rely on meta-training tasks for transfer(Andrychowicz et al., 2016). This design therefore writes candidates, seeds, grammar version and order to the log, and writes the final rule separately to optimizer.py.

Lion's sign update uses one time scale and a constant magnitude, and program search has so far looked only for such single-state rules; combining two time scales with a bounded magnitude inside the frozen grammar is the gap this design addresses.

3Method

3.1Overall structure

The searcher generates at most 256 candidates from the fixed primitive table, compiles each into the same update interface, computes proxy scores on the fixed gradient stream in lexicographic order, and finally determines a unique choice by score and program hash. At deployment only the chosen program and its hyperparameter declaration are kept.

3.2Definitions

Given the gradient (g_t), RidgeSign maintains fast and slow states (m^f_t,m^s_t) and defines an extrapolated variable, a confidence factor and a difference gate:

mtf=βfmt−1f+(1−βf)gt,mts=βsmt−1s+(1−βs)gt(1)
zt=mtf+α(mtf−mts),ct=|zt||zt|+τ+ε,qt=1+sign(mtf−mts)2(2)

Here ε>0 serves only numerical stability; when the fast–slow difference is negative qt=0, when it is zero qt=1/2, and when it is positive qt=1.

3.3Algorithm

The algorithm returns sign(zt)ctqt plus the weight-decay term. It corresponds to optimizer.py:RidgeSign.update; candidate generation and replay correspond to search.py:programs, and logging uses search_log.jsonl.

3.4Complexity

Each step needs only two element-wise EMAs, one extrapolation, one sign and one bounded division; time complexity is (O(d)) and extra state is (2d), where (d) is the number of parameter elements. Candidate generation performs at most 256 fixed proxy replays, and search storage grows linearly with the candidate log.

4Design Rationale

The fast state responds to recent directions and the slow state keeps a longer time scale, so their difference can serve as a signal of short-term change relative to the long term. ct limits the magnitude to [0,1] and decays continuously as the extrapolated value approaches zero, avoiding the update jumps a hard threshold would cause. qt keeps the full update only on coordinates where the fast state is not below the slow state; where the fast state is below the slow state the coordinate is zeroed, and where the difference is exactly zero half is kept.

Proposition 1.

For τ>0, the confidence factor ct is bounded and continuous; when |zt|≫τ, the update magnitude approaches that of the sign update.

Proof sketch.

A non-negative numerator and a positive denominator give 0≤ct<1, and differentiating with respect to |zt| gives monotonicity; the limit |zt||zt|+τ→1 gives the second claim. ∎

Differences from existing methods

Compared with Lion, RidgeSign adds a slow state, extrapolation and a continuous magnitude; compared with Adam, it keeps only first-order states and stores no second moment; compared with learned optimizers, the candidate space, seed and deployed rule are frozen after search, with no meta-training at run time(Andrychowicz et al., 2016).

5Scope and Limitations

The rule assumes the gradient stream can be described by two time scales and that the fixed primitives suffice to express the differences between candidates. When the gradient has almost no directional noise, the confidence gate is close to constant and the extra state brings little; when the gradient distribution or parameter scale changes greatly, τ and the two decay rates need to be re-chosen. The search proxy only determines the candidate order; transfer across settings still has to be verified independently by the evaluation environment.
