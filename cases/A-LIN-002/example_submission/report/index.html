Gated Linear Attention in Chunkwise-Parallel Form: A Reference Mixer for Associative Recall

ABench reference submissionStandard reference for task statement standard v2.1
Abstract

This submission is the anchor's layer, re-implemented in plain PyTorch as the reference point for the task. Each head keeps a matrix state updated as S_t = diag(α_t) S_{t−1} + k_tᵀ v_t with a data-dependent, per-channel decay α_t, and reads it out with o_t = q_t S_t (Yang et al., 2024). Training uses the chunkwise-parallel form: within a chunk of 64 tokens the contributions are computed as a masked, decay-weighted attention matrix, and across chunks through the carried state, which makes the cost linear in the sequence length (Katharopoulos et al., 2020). Associative recall probes how much of the context such a fixed-size state can retrieve (Arora et al., 2023).

1Introduction

Linear attention replaces the growing key-value cache of softmax attention by a fixed-size state, which makes inference cost constant per token but limits what can be recalled (Katharopoulos et al., 2020; Arora et al., 2023). The update rule decides what the state keeps: gated linear attention lets each key channel decay at a learned, input-dependent rate (Yang et al., 2024); the delta rule instead overwrites the value stored for a key (Schlag et al., 2021; Yang et al., 2024).

Changes relative to the anchor. Each item states what this submission does differently and where it is in the code.

  1. A full-rank gate projection replaces the anchor's low-rank gate. — mixer.py: Mixer.__init__ (g)
  2. No normalisation of the output before gating, and fp32 computation inside the layer. — mixer.py: Mixer.forward
  3. Chunkwise-parallel computation with chunk size 64 in plain PyTorch instead of the anchor's Triton kernels. — mixer.py: Mixer.forward (chunks)

2Related Work

MQAR presents several key-value pairs and then queries keys in random order; a model succeeds only if its state stores many associations with little interference (Arora et al., 2023). The chunkwise form of linear recurrences trades a small quadratic block for parallelism within a chunk (Yang et al., 2024).

Decay-based updates forget uniformly, while delta-rule updates overwrite selectively but are harder to parallelise; combining selective overwriting with gating at linear cost is the open gap for entries.

3Method

3.1Layer

With d_k = d_v = d_model / h per head: q, k, v and a gate g are linear projections of x; log α = logsigmoid(g)/16 per key channel. Within chunk c, with cumulative log decays G_i = Σ_{s ≤ i} log α_s, the output is o_i = (q_i ⊙ e^{G_i}) S_c + Σ_{j ≤ i} [Σ_d q_{id} k_{jd} e^{G_{id} − G_{jd}}] v_j, and the state moves on as S_{c+1} = diag(e^{G_C}) S_c + Σ_j (k_j ⊙ e^{G_C − G_j})ᵀ v_j. Pairwise differences G_i − G_j ≤ 0 keep every exponential in (0, 1]. The output is gated by swish(W_r x) and projected by W_o.

3.2Complexity

For T tokens, chunk size C and head dimension d: O(T · C · d) for the intra-chunk part (with the pairwise decay tensor, O(T · C · d) memory per head) and O(T · d²) for the state updates, i.e. linear in T.

4Design Rationale

Computing decay differences pairwise instead of as e^{G_i} · e^{−G_j} avoids overflow for long chunks at the cost of a larger intermediate tensor; the temperature 1/16 keeps initial decays close to 1 so that early training does not forget the key-value pairs before the queries arrive.

5Scope and Limitations

A decay-only update cannot remove a stale association for a key without also fading the others; delta-rule and hybrid updates address this. The implementation is a reference in PyTorch, not a fused kernel.
