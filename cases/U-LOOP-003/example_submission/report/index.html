A Learned Local Lookup Model: A Fixed-Context Baseline for Length Generalisation

ABench reference submissionStandard reference for task statement standard v2.1
Abstract

This submission gives a deliberately limited baseline for learning algorithms that must extrapolate in length. Each output token is predicted from a fixed window of aligned input tokens by the most frequent output observed for that window in the training samples, and the output length is a learned linear function of the input length. The model has a fixed receptive field and no iteration, so it extrapolates only rules that are local. It is the counterpoint to the anchor's looped transformers, whose number of iterations grows with the problem size (Fan et al., 2024).

1Introduction

Length generalisation asks whether a model trained on short instances computes the same function on longer ones. Fixed-depth models typically fail when the computation needs a number of sequential steps that grows with the length (Delétang et al., 2023), while models that iterate a shared block can adapt their depth to the input (Dehghani et al., 2019; Fan et al., 2024).

Changes relative to the anchor. Each item states what this submission does differently and where it is in the code.

  1. A most-frequent-output lookup over fixed windows of aligned input tokens replaces the anchor's looped transformer. — model.py: keys, predict; train.py: main
  2. The output length is a least-squares linear function of the input length. — train.py: main (lstsq)

2Related Work

Copy needs only a position-wise rule; binary addition needs a carry that can propagate across all positions; parity needs a running XOR over the whole input. The anchor shows that a looped transformer trained with an iteration count tied to the length generalises on these tasks (Fan et al., 2024).

Looped transformers iterate a shared block a number of times that grows with the input; fixed-window models cannot; this reference has a fixed window, which isolates the gap the anchor's looping addresses.

3Method

3.1Model

For output position i the key is the tuple of the last four input tokens up to position i (for addition, of both operands, which the public task definition places one after the other). On 200 samples per length and task, the model counts the output token at each position under each key and keeps the most frequent one; unseen keys fall back to the most frequent output overall. The output length is fitted as α·len(x) + β by least squares.

3.2Complexity

Training is linear in the number of sampled tokens; the table holds at most V^{2w} keys for vocabulary V and window w = 4. Prediction is O(L · w) per problem.

4Design Rationale

The baseline isolates one factor, the receptive field. Copy is solved at every length because its rule is local; addition is right whenever no carry crosses more than the window; parity is at chance beyond the window. Any entry that iterates a learned step should beat it on exactly the last two tasks.

5Scope and Limitations

There is no state carried between positions and no iteration, so the model cannot represent carries or running sums of unbounded length; these are the capabilities the task is designed to measure.
