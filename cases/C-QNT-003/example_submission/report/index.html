Round-to-Nearest Group Quantization: The Calibration-Free Reference for 4-bit Weights

ABench reference submissionStandard reference for task statement standard v2.1
Abstract

This submission gives the calibration-free reference for weight-only quantization. Every weight matrix of Qwen2.5-0.5B, including the tied embedding, is split into groups of 128 input channels; each group is mapped affinely onto 16 levels with an fp16 scale and an 8-bit zero point and rounded to the nearest level. Two 4-bit codes are packed per byte, vectors stay in fp16, and loading dequantizes into a standard bf16 model. Round-to-nearest is the baseline that error-compensating methods such as GPTQ (Frantar et al., 2023) and activation-aware scaling (Lin et al., 2024) improve on.

1Introduction

At around four bits per weight, how each weight is rounded matters: rounding errors in different weights of a row add up in the layer's output. GPTQ chooses the rounding of each column to compensate the error of earlier columns using second-order information from calibration activations (Frantar et al., 2023); AWQ protects salient channels by rescaling (Lin et al., 2024). Round-to-nearest ignores both and therefore isolates the effect of the format itself.

  1. Asymmetric 4-bit round-to-nearest per group of 128 input channels with fp16 scales and zero points; no calibration and no error compensation, unlike the anchor. — quantize.py: _q, _dq
  2. The tied embedding is quantized as well, so the whole model fits the 4.25-bit budget. — quantize.py: quantize

2Related Work

Group-wise affine quantization stores, for each group of g weights, a scale s and zero point z, and represents a weight w by round(w/s + z) clipped to [0, 2^b − 1] (Dettmers & Zettlemoyer, 2023). Smaller groups reduce error at the cost of more metadata; at b = 4 and g = 128 with fp16 scales and 8-bit zero points the overhead is 3/16 of a bit.

GPTQ and AWQ use calibration activations to compensate or avoid rounding error; round-to-nearest uses none, which is the gap entries are expected to close.

3Method

3.1Format

For a matrix W (out × in), the input dimension is padded to a multiple of 128 and split into groups. Per group, s = (max − min)/15 and z = round(−min/s); codes q = clip(round(w/s + z), 0, 15) are packed two per byte. The artifact holds the packed codes, scales, zero points, all vectors in fp16 and the model's configuration files. load() reconstructs w = (q − z)·s in bf16 and ties the output head to the embedding.

3.2Complexity

Quantization is a single pass over the weights, O(P) for P parameters, with no calibration. The artifact uses about 4.19 bits per parameter. Inference runs at bf16 speed after dequantization at load time.

4Design Rationale

Quantizing the embedding is necessary: in a 0.5B model it holds more than a quarter of the parameters, and a bf16 embedding alone would exceed the size budget. Asymmetric groups follow the skewed ranges of individual rows better than symmetric ones at four bits.

5Scope and Limitations

No calibration data is used, so outlier input channels and correlated rounding errors are not compensated; the remaining 0.06 bits of budget are unused. Error compensation, rescaling and mixed precision are the levers for entries.
