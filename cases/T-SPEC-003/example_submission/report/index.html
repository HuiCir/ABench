Windowed Picard Iteration: Draft-and-Verify Rounds for DDIM Sampling

ABench reference submissionStandard reference for task statement standard v2.1
Abstract

This submission transfers the draft-and-verify structure of speculative decoding (Leviathan et al., 2023; Chen et al., 2023) to diffusion sampling with the parallel-in-time scheme of ParaDiGMS (Shih et al., 2023). The deterministic DDIM update (Song et al., 2021) is affine in the state given the network's prediction, so a window of four future states can be drafted, evaluated by the network in one batched round, and re-derived from the window start in closed form. Sliding the window by two states per round covers 2R DDIM steps in R rounds with four evaluations per image per round. Unlike speculative decoding, the verification is not exact: there is no acceptance test, only repeated refinement.

1Introduction

Speculative decoding makes autoregressive generation faster without changing its output by letting a cheap process propose several tokens and the target model check them all in one parallel pass. Diffusion sampling has the same sequential bottleneck, one network call per step, but its steps are continuous, so verification becomes a fixed-point problem rather than an accept-or-reject decision.

Changes relative to the anchor. Each item states what this submission does differently and where it is in the code.

  1. Speculative decoding's prefix acceptance is replaced by a fixed slide of two states per round, with every state evaluated twice. — sampler.py: WINDOW, ADVANCE, sample
  2. The window update uses the closed-form affine DDIM recursion instead of ParaDiGMS's cumulative drift sum. — sampler.py: coefficients, sample

2Related Work

Speculative decoding and speculative sampling verify draft tokens in parallel and accept a prefix, preserving the target distribution (Leviathan et al., 2023; Chen et al., 2023). ParaDiGMS writes the sampling ODE as a fixed-point equation over a window of time steps and solves it by Picard iterations whose drift evaluations run in parallel, sliding the window by the number of converged steps (Shih et al., 2023). DDIM gives the deterministic sampler whose steps the window covers (Song et al., 2021), for the DDPM model in use (Ho et al., 2020).

Picard windows spend parallel compute to save sequential steps but have no exact acceptance rule; a test that tells which drafted states are good enough, as speculative decoding has for tokens, is the gap.

3Method

3.1Window iteration

The grid has N = 2R uniformly spaced timesteps. With c_j = sqrt(ᾱ_{j+1}/ᾱ_j) and d_j = sqrt(1 − ᾱ_{j+1}) − sqrt(ᾱ_{j+1}(1 − ᾱ_j)/ᾱ_j), DDIM is x_{j+1} = c_j x_j + d_j ε(x_j, t_j). All states start as copies of the initial noise. Each round evaluates ε at the current guesses of the four states s … s+3 in one call, recomputes x_{s+1} … x_{s+4} from x_s with these predictions, copies the newest state into the guesses further ahead, and advances s by two.

3.2Complexity

R rounds, 4 evaluations per image per round (4R in total, against R for DDIM), and N + 1 stored states per image.

4Design Rationale

Because the DDIM step is affine given ε, re-deriving the window after a parallel evaluation costs nothing; each state is evaluated once as a draft and once more after its predecessors were refined, which is enough for the early, smooth part of the trajectory and gives a sampler that behaves like DDIM with twice the steps.

5Scope and Limitations

The window advances by a fixed two states without checking convergence, x₀ is not clipped, and the drafts are naive copies of the newest state instead of predictions from a cheap model.
