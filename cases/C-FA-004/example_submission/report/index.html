Blockwise Attention with a Recomputing Backward Pass in Plain PyTorch

ABench reference submissionStandard reference for task statement standard v2.1
Abstract

This submission gives a correct, memory-bounded reference for trainable exact attention. A custom autograd function processes blocks of queries for all heads at once; the forward pass keeps only the output and the log-sum-exp of each query row, and the backward pass recomputes each block's probabilities from them, which is the recomputation idea of the anchor (Dao et al., 2022). Unlike the anchor, every block is a sequence of separate matrix products through global memory, so it is not IO-aware; fusing these steps into on-chip tiles (Dao, 2023; Tillet et al., 2019) is what entries are expected to add.

1Introduction

Standard attention stores the T × T probability matrix for the backward pass, which makes memory quadratic in sequence length. Storing only per-row softmax statistics and recomputing probabilities in the backward pass keeps memory linear; doing so inside fused kernels also makes it faster, because the quadratic intermediates never leave on-chip memory.

Changes relative to the anchor. Each item states what this submission does differently and where it is in the code.

  1. The anchor's fused tiles are replaced by blocks of separate PyTorch matrix products over all heads at once. — kernel.py: _Attention.forward, _Attention.backward
  2. The block length is derived from the size of q so that one block of fp32 scores never exceeds it. — kernel.py: _block
  3. dK and dV are accumulated in fp32 across query blocks and cast to bf16 once. — kernel.py: _Attention.backward

2Related Work

FlashAttention tiles the forward and backward passes so that scores and probabilities live only in shared memory, saving the log-sum-exp per row for the backward pass (Dao et al., 2022). FlashAttention-2 reorders the loops to parallelise over sequence blocks and reduces non-matrix-multiply work (Dao, 2023). Online softmax computes the normaliser in one pass over the keys (Milakov & Gimelshein, 2018), and memory-efficient attention without fusion processes queries in chunks (Rabe & Staats, 2021). Triton makes such tiled kernels expressible in Python (Tillet et al., 2019).

Chunking bounds memory but not traffic; the gap between this reference and SDPA is the cost of materialising each block's intermediates in global memory.

3Method

3.1Forward and backward passes

The block length b is the largest value (between 16 and 256) for which a block of fp32 scores for all heads is no larger than q. For each block of queries the forward pass computes the scores against all keys, applies the causal mask, and stores the normalised output and the row log-sum-exp. The backward pass first forms Δ = rowsum(dO ⊙ O); for each block it recomputes P = exp(S − lse), accumulates dV += Pᵀ dO and dK += dSᵀ Q · scale in fp32 with dS = P ⊙ (dO Vᵀ − Δ), and writes dQ = dS K · scale.

3.2Complexity

Work is O(B H T² D) for each pass, the same as standard attention; memory beyond inputs and outputs is O(B H T) for the statistics plus one block of scores, bounded by the size of q.

4Design Rationale

Recomputation with saved row statistics is the part of the anchor that makes the backward pass memory-linear; it can be written correctly in a few dozen lines of PyTorch, which makes it a dependable starting point whose remaining gap to SDPA is purely about data movement.

5Scope and Limitations

Each block launches several kernels and round-trips its fp32 intermediates through global memory; causal blocks still compute masked-out scores; and the Python loop over blocks adds overhead at short sequence lengths.
