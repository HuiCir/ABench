A Plain Data-Parallel AdamW Recipe for a GPT-2 Medium-Scale Speedrun

ABench reference submissionStandard reference for task statement standard v2.1
Abstract

This submission gives the reference recipe for the four-GPU pretraining speedrun: a dense GPT-2 Medium-shaped decoder (24 layers, width 1,024, about 354M parameters with tied embeddings) with rotary position embeddings (Su et al., 2021), RMSNorm, QK normalisation and a ReLU² MLP (So et al., 2021), trained with AdamW (Loshchilov & Hutter, 2019) at 0.5M tokens per step under data parallelism, bf16 autocast and torch.compile. The token budget of about 4.7B follows a compute-optimal reading of the anchor (Hoffmann et al., 2022) rather than the aggressive over-training of speedrun records. The recipe is intentionally conventional: the optimizer, schedule and kernel choices of the speedrun's record history (Jordan & contributors, 2024) are the space that entries are expected to explore.

1Introduction

Time to a fixed loss rewards both statistical efficiency (fewer tokens to the target) and hardware efficiency (more tokens per second). The anchor quantifies the first through compute-optimal scaling: for a given compute budget, parameters and tokens should grow together (Hoffmann et al., 2022). The modded-nanogpt speedrun shows how far the second, together with optimizer changes, can be pushed on fixed data.

Changes relative to the anchor. Each item states what this submission does differently and where it is in the code.

  1. A compute-optimal token budget (about 4.7B tokens for 354M parameters) instead of over-training. — train.py: STEPS
  2. Conventional AdamW with data parallelism, bf16 autocast and torch.compile; none of the speedrun's optimizer changes. — train.py: main
  3. Rotary embeddings, RMSNorm, QK normalisation and a ReLU² MLP in a GPT-2 Medium-shaped decoder. — model.py: Block.forward, Rotary

2Related Work

Rotary embeddings encode relative positions in attention (Su et al., 2021); normalising queries and keys bounds attention logits and stabilises large learning rates; the squared ReLU activation improves language-model quality at equal compute (So et al., 2021). Data-parallel training with gradient accumulation scales the batch across GPUs with one all-reduce per step.

Compute-optimal scaling fixes the token budget, and speedrun records improve tokens per second and optimizers; combining both under a fixed four-GPU setup is the gap this conventional recipe leaves.

3Method

3.1Model and training

Each block applies RMSNorm, attention with rotary embeddings and RMS-normalised queries and keys (scaled-dot-product attention, causal), then RMSNorm and an MLP of width 4,096 with ReLU². Output projections are initialised with standard deviation 0.02/sqrt(48). Each of 4 GPUs processes 8 micro-batches of 16 × 1,024 tokens per step (gradient synchronisation on the last), gradients are clipped at 1.0, and AdamW uses β = (0.9, 0.95), weight decay 0.1 on matrices and a peak learning rate of 1.5e-3 with 250 warm-up steps and linear decay to zero over 9,000 steps. Each rank reads disjoint contiguous token slices.

3.2Complexity

About 6 · N · D floating-point operations for N ≈ 354M parameters and D ≈ 4.7B tokens, i.e. about 1e19, plus attention at sequence length 1,024. Memory per GPU holds the model, AdamW state and activations of one micro-batch.

4Design Rationale

A conventional, well-understood recipe gives a reproducible reference whose timing the operator can calibrate on the evaluation node. Rotary embeddings, QK-norm and ReLU² are low-risk improvements over the original GPT-2 that are standard in current small-model training.

5Scope and Limitations

The number of steps has not been calibrated against the 2.92 target on the reference node, and AdamW at a fixed sequence length is far from the speedrun's state of the art; orthogonalised optimizers, longer and variable sequence lengths, FP8 matrix multiplications and better data ordering are the obvious levers.
