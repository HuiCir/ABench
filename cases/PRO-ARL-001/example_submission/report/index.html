DAPO with a Python Tool and Masked Tool Outputs

ABench reference submissionStandard reference for task statement standard v2.1
Abstract

This submission applies DAPO (Yu et al., 2025) to tool-integrated reasoning: Qwen3-4B-Base (Yang & Team), 2025) answers with interleaved Python calls, rollouts are sampled with the evaluator's own tool loop, and the tokens of tool outputs are masked out of the policy loss, as in ReTool-style training (Feng et al., 2025). Group-normalised advantages follow GRPO (Shao et al., 2024); clip-higher, dynamic sampling, the token-mean loss and overlong shaping follow DAPO.

1Introduction

A tool changes what the policy has to learn: when to call it, what to compute and how to use the result. Training with the same tool loop that the evaluation uses removes a mismatch between training and evaluation.

Changes relative to the anchor. Each item states what this submission does differently and where it is in the code.

  1. Rollouts use the evaluator's tool loop and tool outputs are masked out of the loss, which DAPO (text only) does not have. — train.py: masks; src/rollout.py
  2. The KL penalty is removed and the learner and the sampler share one node with an in-place weight reload. — train.py: main; src/rollout.py: worker

2Related Work

GRPO normalises rewards within a group of answers to the same problem (Shao et al., 2024); DAPO adds decoupled clipping, dynamic sampling, token-level averaging and overlong reward shaping (Yu et al., 2025); ReTool trains interleaved code execution with outputs excluded from the loss (Feng et al., 2025).

3Method

Ranks on GPUs 1-3 train with FSDP; a vLLM worker on GPU 0 reloads the weights after every step and samples 64 problems x 16 answers. Reward is 1 for a correct boxed integer minus a linear penalty over the last 2,048 of the 16,384 tokens; groups with identical rewards are dropped and refilled; eps_low 0.2, eps_high 0.28, no KL term, learning rate 1e-6, 400 steps; a checkpoint every 20 steps.

4Design Rationale

Masking tool outputs keeps the policy from being trained to predict the interpreter; dynamic sampling keeps every group informative, which matters when a base model starts with near-zero accuracy on hard problems.

5Scope and Limitations

One update per batch, no curriculum and no value model; the in-place weight reload relies on the V0 vLLM engine. Nothing here has been run in this build.
