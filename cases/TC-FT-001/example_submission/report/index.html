Hashed n-gram Linear Classifier: A CPU Baseline for Topic Classification

ABench reference submissionStandard reference for task statement standard v2.1 (a baseline that does not aim to be best)
Abstract

This submission gives a baseline for CPU-budgeted topic classification. Following the anchor's observation that a linear model over a bag of n-grams is a strong and fast text classifier (Joulin et al., 2017), documents are mapped to a fixed 2^20-dimensional space of unigram and bigram counts with the hashing trick (Weinberger et al., 2009), re-weighted with sublinear tf-idf (Salton & Buckley, 1988), and classified by a linear model trained with stochastic gradient descent on the modified Huber loss (Zhang, 2004) with iterate averaging (Polyak & Juditsky, 1992). Training is a single streaming pass structure with no vocabulary to build, and prediction is one sparse matrix product.

1Introduction

The task rewards accuracy under a minimum prediction throughput on eight CPU cores, with the model trained once in the sandbox. Both favour models whose cost is linear in the number of tokens and whose parameters fit in memory without a vocabulary pass. Bag-of-n-gram linear models satisfy both and are known to be competitive with much larger neural encoders on news topic classification (Joulin et al., 2017; Zhang et al., 2015).

As a reference version this submission uses only mature components; its purpose is to be complete in interface, timing and report format and to leave the room for improvement to the entries.

Changes relative to the anchor. Each item states what this submission does differently and where it is in the code.

  1. A sparse linear model over hashed unigram and bigram counts replaces the anchor's averaged learned embeddings, so there is no embedding layer and no vocabulary. — model.py: vectorizer, predict
  2. Sublinear tf and idf weighting with L2 normalisation of each document, which the anchor does not use. — train.py: main (TfidfTransformer); model.py: predict
  3. Averaged SGD on the modified Huber loss replaces the anchor's softmax trained with SGD and a hierarchical softmax option. — train.py: main (SGDClassifier)

2Related Work

fastText represents a document by the average of learned embeddings of its words and hashed bigrams and trains a linear softmax classifier on top (Joulin et al., 2017). The hashing trick maps an unbounded feature set into a fixed number of buckets with a hash function, trading a small collision rate for constant memory and no vocabulary construction (Weinberger et al., 2009). Term weighting with inverse document frequency down-weights ubiquitous tokens (Salton & Buckley, 1988).

Neither fastText's learned embeddings nor the hashing and weighting components address prediction throughput directly; this reference keeps the anchor's bag of n-grams but drops the learned embedding layer, which leaves a gap in word-similarity modelling that entries can close.

3Method

3.1Features

Each document is lower-cased and split into word tokens; unigrams and adjacent bigrams are hashed into 2^20 non-negative count features. Counts are transformed to 1 + log(tf) and multiplied by an inverse document frequency estimated on the training documents only, then each row is L2-normalised.

3.2Classifier

A one-vs-rest linear classifier is trained by stochastic gradient descent on the modified Huber loss, which is a smoothed hinge loss with bounded gradients (Zhang, 2004), with an L2 penalty of 2e-6 and 15 epochs. The averaged iterate is used for prediction, which reduces the variance of the final SGD iterate (Polyak & Juditsky, 1992). The implementation uses scikit-learn (Pedregosa et al., 2011).

3.3Complexity

With T tokens in the training set, featurisation costs O(T) and each SGD epoch O(nnz(X)) = O(T); memory is O(nnz(X) + 4 · 2^20) for the data and the weights. Prediction costs O(T') for T' held-out tokens.

4Design Rationale

Hashing removes the vocabulary pass and bounds memory, which matters more on a CPU budget than the small loss from collisions at 2^20 buckets. Sublinear tf and idf weighting make a linear model less sensitive to document length and to frequent function words. The modified Huber loss keeps the robustness of the hinge loss while allowing probability-like scores, and averaging makes the result less sensitive to the learning-rate schedule.

5Scope and Limitations

The model has no notion of word similarity beyond shared n-grams and cannot use subword information; both are natural directions for entries, as are learned low-dimensional embeddings in the style of the anchor.
