# ABench case K-KB-001: Faster kernels for 30 KernelBench Level-1 operators: correct on five input distributions, timed against eager PyTorch and torch.compile

Case built to task statement standard v2.1 from the template of K-FA-003. Anchor: Anne Ouyang, Simon Guo, Simran Arora, Alex L. Zhang, William Hu, Christopher Ré, Azalia Mirhoseini, *KernelBench: Can LLMs Write Efficient GPU Kernels?*
(arXiv:2502.10517).

## Status

- Judge: `harness` (shared stage protocol `harness/abench_stage.py`), activation **awaiting_data**: the operator still has to
  freeze the data (below); until then `tools/oj_eval.py` returns `judge_pending` for this case.
- Reference submission (`example_submission/`): Not executed yet: the evaluator and the reference need PyTorch, Triton and a GPU, which were not available where the case was built; the operator runs them at activation and checks that the reference is correct on every problem and reports no changed torch entry points. Checked in the container: the 30 problem files at the pinned commit (sha256), their input shapes after the overrides (all within 1 GiB of fp32, computed from get_inputs() with a shape-only stand-in for torch), the Triton kernel's formulas against PyTorch's definitions, and the problem loading and seed plumbing of the prepare module.
- No number in the case files is a result: there are no training curves or reference scores.
