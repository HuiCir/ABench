A Prelude-Core-Coda Decoder with Input Injection, Trained over Random Loop Counts

ABench reference submissionStandard reference for task statement standard v2.1
Abstract

This submission spends the parameter budget of a 4-layer decoder on two prelude layers, one core layer that is applied repeatedly and one coda layer, following the recurrent-depth design of Geiping et al. (Geiping et al., 2025) and the weight sharing across depth of the anchor (Dehghani et al., 2019). Before every core iteration a linear adapter combines the current state with the prelude output, so the input stays visible at depth. Each training step draws the loop count uniformly from 1 to 8, so the model is trained for every count it is evaluated at. It has not been run yet: it needs PyTorch and a GPU, which were not available where the case was built.

1Introduction

Sharing weights across depth decouples compute from parameters: a looped model can think longer without growing. At a fixed parameter budget the question is how much loss each extra loop buys, and whether the model degrades gracefully when run with fewer loops than it prefers.

Changes relative to the anchor. Each item states what this submission does differently and where it is in the code.

  1. The four-layer budget is split into two prelude layers, one looped core layer and one coda layer instead of four distinct layers. — model.py: Looped.__init__, PRELUDE, CODA
  2. The prelude output is injected before every core iteration through a linear adapter initialised near identity. — model.py: Looped.forward, adapter
  3. Each training step uses a loop count drawn uniformly from 1 to 8. — model.py: Looped.loss

2Related Work

The anchor applies one transformer layer recurrently with adaptive halting (Dehghani et al., 2019); ALBERT shares all layers to save parameters (Lan et al., 2020). Recurrent-depth language models add a prelude and coda around a looped core, inject the input at every iteration and train with random iteration counts (Geiping et al., 2025); looped transformers generalise algorithmic tasks to longer inputs (Fan et al., 2025); deep-equilibrium models take the loop to its fixed point (Bai et al., 2019).

3Method

e ← prelude(embed(x)) with two blocks; h ← e; for each loop, h ← core(W [h; e]) with one block; logits ← coda(h) projected by the tied embeddings. W starts as [I, 0.1 I] so that the first iterations nearly keep the state. Residual output projections are initialised for an effective depth of seven. The training loss is the cross-entropy at a loop count drawn uniformly from 1–8 per step, with backpropagation through all iterations.

4Design Rationale

Two prelude layers build token features before recurrence starts; one core layer keeps the cost of a loop low so that eight loops stay well inside the compute gate; input injection prevents the state from drifting away from the input over many iterations; and uniform loop counts in training make every evaluated count in-distribution.

5Scope and Limitations

Backpropagating through up to eight iterations makes training steps slower than the baseline's; the loop count is fixed at inference rather than adaptive; and the design has not been run yet.
