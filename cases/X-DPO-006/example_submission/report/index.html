Direct Preference Optimisation of Low-Rank Updates

ABench reference submissionStandard reference for task statement standard v2.1
Abstract

This submission applies the anchor's objective unchanged (Rafailov et al., 2023): the log-sigmoid of β times the difference of the chosen and rejected answers' log-ratios to the starting model, with β = 0.1, minimised over rank-16 LoRA updates (Hu et al., 2022) of SmolLM2-360M-Instruct on 20,000 of the public UltraFeedback pairs (al., 2024). It is the plain floor: no length control, no data filtering, one epoch. It has not been run yet: it needs PyTorch and the SmolLM2 weights, which were not available where the case was built.

1Introduction

Offline preference optimisation trains on fixed pairs without a reward model. Its known failure modes are drift from the starting model and longer answers that a judge rewards for their length; the case measures both next to the win rate.

Changes relative to the anchor. Each item states what this submission does differently and where it is in the code.

  1. The policy is restricted to rank-16 updates of all projections, which bounds drift from the reference. — train.py: main; src/lora.py: attach

2Related Work

DPO turns the RLHF objective into a classification loss on pairs (Rafailov et al., 2023); IPO bounds the implied margin (al., 2024); SimPO drops the reference model and normalises by length (Meng et al., 2024); length-controlled win rates correct judge preferences for length (Dubois et al., 2024).

3Method

For a pair (x, y_w, y_l): loss = −log σ(β[(log π(y_w|x) − log π_ref(y_w|x)) − (log π(y_l|x) − log π_ref(y_l|x))]), with π_ref the starting model, log-probabilities summed over answer tokens in the evaluator's chat template, answers cut at 512 tokens. AdamW (lr 5e-5), 8 pairs per step, gradient clipping at 1, one pass over 20,000 pairs.

4Design Rationale

Low-rank updates limit drift by construction; using the evaluator's template in training avoids a mismatch between the pairs and generation.

5Scope and Limitations

DPO tends to lengthen answers and lowers the likelihood of both answers of a pair; nothing here counters either. It has not been run yet.
